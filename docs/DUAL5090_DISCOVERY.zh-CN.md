# 双 5090 本地验证协议

研究问题：在固定支持内容下，即时任务收益与参数学习收益是否一致；上下文混合或本地蒸馏能否改变差异。

本轮为单模型、单训练种子的探索实验，主要用于筛查后续对照条件。

本轮测量的是更新参数后、撤掉支持时的任务能力；尚未测量对后续新任务的学习速度，也未运行多轮持续学习或在线 agentic RL。

## 数据与支持

- pilot：12 个开发任务，每类 3 个；无支持、早期、随机时机、延迟支持，各 1 个确定性 rollout。
- train：16 个独立训练任务，每类 4 个；无支持和 pilot 中最好的支持条件，各 2 个采样 seed。
- probe：12 个独立开发 probe，每类 3 个；只用 H0 评估模型能力，最终 seen/unseen 测试均不运行。
- 支持来源是固定手写的公开策略文本，所有任务复用相同策略，无任务私有位置、专家计划或付费 API。它不能代表前沿模型教师。
- 支持条件的选择只使用 pilot；相同成功率时按 early、delayed、random_timing 顺序打破平局。即使即时分数相同，仍可检查学习结果是否不同。

pilot 上的最优分数参与了条件选择，有选择偏差；其区间仅作描述，不作为所选支持优于其余条件的确认性检验。

## 三个训练分支

每个 source arm 的成功轨迹固定为一份 corpus，三个方法使用相同的示范成员和标签。支持提示过长导致的样本过滤在三个方法中统一实施。

1. target_sft：去除显式支持消息，在基础上下文下对成功动作做 SFT。
2. mixed_sft：同一 corpus 的一半示范使用支持上下文，一半不使用；不新增示范或更新步数。
3. context_distill：学生在无支持上下文下，以 CE 与冻结本地基础模型在有支持上下文下的 KL 各 50% 训练。

蒸馏 teacher 是同一个本地 Qwen3-4B 的冻结副本。额外 teacher forward 的 token 和显存单独记录。该分支是本地上下文蒸馏对照；教师前向开销使其计算量高于普通 SFT。

首轮训练使用 LoRA、单进程单卡、global batch=4、64 次参数更新、上下文上限 2,048、一个训练 seed（101）。两张 GPU 并行独立训练/评估任务。若有初步差异，再增加独立训练种子和任务数。

不同来源 arm 的 corpus 可以有不同的成功任务组成；固定更新次数并不能匹配其任务覆盖或实际计算量。这是 harness 改变训练数据的总效应筛查。若出现差距，需补充按任务类型/轨迹数量匹配的对照，才能区分覆盖、质量与支持依赖。

## 指标与比较

即时差距为 ΔS = S(support)-S(none)。每种训练方法的 source-arm 差距为 ΔL_m = J(support,m,H0)-J(none,m,H0)。

- 若 ΔS 与 ΔL_target 方向不同，得到“即时收益与持久收益不同”的候选现象。
- 若混合上下文或蒸馏使该差距缩小/改变，优先考虑分布匹配或已知内化方法的解释。
- 若差距在这些分支仍存在，再增加候选支持、独立种子和外部环境验证。
- 只有两个 source arms 和一个训练种子时，不能声称已经学到可预测的跨模型改进规律。

12 个 probe 上一个成功任务就对应 8.33 个百分点。分数相等或区间覆盖零都不能证明两种方法等效；训练未显效也不能直接否定 harness 对学习的作用。本轮不凭一个 seed 宣称“稳定差异”，也不进行 meta-RL 或可迁移预测器训练。

## 接口校准

真实执行核查发现当前 TextWorld 的放置命令是 `move OBJECT to RECEPTACLE`。旧式 `put ... in/on ...` 等词法变体由统一兼容层转换，不查询环境状态。所有模型使用相同系统提示。

接口修正前的回合保存在 calibration-* 目录，不用于学习效应结论。系统提示哈希现在进入运行指纹，防止混合不同接口设置。

## 产物

配置、支持缓存、模型轨迹、训练 corpus、adapter 和逐阶段结果保存在 `runs/dual5090-v1/`。结果报告包含样本数量、失败率、token、额外教师计算及原始成功数。

已完成轨迹采集后，可运行下列入口恢复尚未完成的训练/评测。必须先释放本实验在 19080/19081 端口的基础模型服务，保证每张卡只运行一个训练或评测进程；不要停止其他用户的 GPU 进程。

```bash
PYTHONPATH=src .venv-model/bin/python scripts/train_and_evaluate_study.py

```
