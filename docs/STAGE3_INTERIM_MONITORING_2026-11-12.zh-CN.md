# Stage 3中途监控与动作构成线索

正式实验仍运行原冻结70模型/4480评测方案。单独增加只读观察器 `scripts/stage3_interim_report.py --watch`，在1、4、8、12、16组两来源×两策略均配齐的种子单元时保存PNG/PDF、原始输入哈希与结果，并上传独立标记INTERIM的W&B记录。该观察计划在首8个模型完成之后设定，用于用户要求的过程监控，不是预注册推断或提前停止规则。

比较前核对原始64任务成绩、组合修订、诊断NLL、相同初始化、任务ID/次数/顺序、768次呈现和256条不同任务内容。未配齐单元、全池检查、条件重复全部保留在原始快照，但不混入成对均值。6项报告检查通过，包括未配齐排除与关键控制不一致时拒绝报告。

首个配齐单元（初始化101，采样101）显示随机选择优于低NLL选择：API 29.69%对17.19%，generic 23.44%对3.12%。这只是一组种子的开发集描述，不代表完整效果。首图与原始数据已[上传W&B](https://forge.coreweave.com/wandb/yanyaoyuan-jawaharlal-nehru-university/learning-harness-lab/runs/262c0863d930-interim-20261112T122632Z)。

## 新的探索性机制审计

`scripts/audit_stage3_action_mix.py`不读取模型评测成绩，只分析16份已冻结调度的最后一条assistant动作标签。动作族按命令首词分类（`go to`统一为`go`），每组核对768次呈现，并报告输入/目标token与基础模型NLL。这个分析是在看过首组成对结果后定义，明确标记探索性。

| 来源 | 随机选择move占比 | 低NLL选择move占比 |
|---|---:|---:|
| API | 10.19% | 3.84% |
| generic | 8.43% | 0.91% |

这里每个数是4个采样调度种子的均值；`move`是放置物体。低NLL组的`open/take`占比增加，`move`占比减少。API两组目标token总量平均分别9824.75与9823.75，generic分别9446.75与9337.25；动作构成差异不能仅描述成输入更短或训练次数不同。

**得到的线索是：匹配任务覆盖仍不能保证任务内部行为覆盖。** 当前不能把动作构成变化直接解释为能力下降的原因，不能把首组结果当成低NLL策略的一般结论。审计CSV、JSON、图见 `output/variance-diagnostic-v1/stage3/action-mix-audit/`。

## 完整结果之后的候选干预

若完整Stage 3仍显示低NLL选择劣于随机，下一步优先比较任务与动作族同时匹配下的随机选择和低NLL选择：

1. 固定每个训练位置的任务ID和动作族，固定逐任务×动作族次数；先检查每组不同内容支持是否足以实现256条预算，不能复制不足支持的组来假装匹配。
2. 在相同配额内随机选择或按低NLL选择内容；固定初始化、呈现次数、更新与评测方式，记录token消耗。两策略都保留，不能仅增加一个可能“救回”低NLL的组。
3. 同时保留原任务匹配比较，从而观察控制动作构成后差异是否缩小。即使缩小，也只支持动作构成解释的一部分，不将其直接叫作已识别的因果中介。

这份候选设计尚未冻结、尚未启动GPU。正式对比、采样配额和预算须在完整Stage 3审计以及支持可行性检查之后单列固定；现有实验不因中途方向改变。
