# 保持JSON接口的公共示例执行校准

本轮使用已固定的32个放置/清洗校准任务，验证示例提示在不改变动作输出格式时的表现。它是查看前轮基础校准之后登记的实现校准，不是独立确认试验。128开发、128确认和官方seen/unseen仍不评测。

## 改变与保持

基础学生仍为Qwen3-4B-Instruct-2507，无adapter。保持原JSON系统指令、当前任务可见观察、JSON动作输出和历史重建逻辑；追加公开ReAct同任务族的两条示例，仅将示例动作转换为规范JSON、移除think/OK。示例路由只读取公开任务目标。没有教师卡、隐藏状态、专家动作查询、反思、重试或跨任务记忆，也不修补模型的输出。

这个条件与上一轮JSON相比主要增加公共示例，与上一轮ReAct相比还移除了思考并统一输出接口，因此不能将跨三条件的差异单独归因于某个推理机制。它为后续JSON监督学生提供格式兼容的共同执行方式，防止把格式迁移混入技能测量。

## 固定预算

同32个校准任务、环境seed11、temperature0、batch8、history12，每回合40次调用/动作和128输出token。32回合，GPU0总计账上限0.5小时、单次1750秒；不足700秒不启动。模型完整文件身份前后核验，每次请求先记attempt，再记响应/错误；未知用量保留，不补零。云端仅汇总。

代码、公共示例和历史校准比较记录在首次调用前冻结。它排在FP32梯度提取完成后执行；如前序失败或GPU0被其他任务占用，则保留现场并停止，不自动重启任何阶段。此排队顺序只管理资源，不按梯度分数或学习效果选择是否执行。

完整结束后报告成功率、逐族数量、真实调用/token/时间，以及同32任务三种基础执行方式的配对成败汇总。不会据训练候选效果切换执行方式。最终学习比较的主要接口、选择规则、种子和任务须再单独冻结。
