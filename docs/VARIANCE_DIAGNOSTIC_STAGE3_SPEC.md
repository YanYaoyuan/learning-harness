# Stage 3：逐任务暴露和任务顺序完全匹配的经验选择对照

日期：2026-11-12。用户已授权结束后继续下一步；这是Stage 2结束后的新协议，主训练前单独冻结。

## 动机与主比较

Stage 2完成68个模型与4,352次评测。同预算全池遍历相对256子集复用的成功率平均差为API +5.18pp、generic +1.27pp；四个初始化内，来源差值随采样种子的波动均下降。

下一步固定更多变量：每个训练位置的任务ID、每个任务出现次数、优化器步数192与样本呈现数768均匹配原全池组。只改变任务内部使用哪些示范及其复用方式。

- `random`：先在每个任务内按规范化学生messages内容去重，再按任务内不同内容数量分配总计256条支持，保证每任务至少1条；按固定采样种子随机选择，在任务内均匀循环重排，嵌入原全池的任务顺序。
- `min_nll`：相同的逐任务去重支持配额，选择基础模型动作NLL最低的不同内容示范（重复副本NLL取均值）；使用同样的任务内重排规则、逐位置任务ID及次数。
- `full_reference`：复用Stage 2全池组34个模型的既有权重和评分；另在本轮开头重新训练API/generic各一个101/101全池模型，作为跨轮条件检查。

两个新选择组各34个模型（每来源4×4交叉初始化/dropout与采样种子，另各一次101/101训练重复），再加2个全池检查，共70个新模型、4,480次新评测。

主对比是来源内部`random − full_reference`以及`min_nll − random`的16个配对单元。前者检验控制逐任务暴露后，任务内部示范覆盖/复用是否仍改变效果；后者是学生可学性代理的基线。两种来源分别报告，跨来源差值作为次要诊断。

低NLL选择用于动作示范级基线，未宣称复现SmartAD的完整轨迹选择和加权目标。低NLL组的成员选择在同一来源中基本固定；采样种子主要改变顺序，因此波动下降本身不等于示范质量更高。报告平均成功率、诊断NLL与所有单元。

## 数据和控制

仅用原训练池API 721条/generic 732条；基础模型NLL评分不更新参数，不使用开发query标签选择示范。评分数据哈希、逐行索引和模型版本均固定。

冻结前的数据审计显示，两个池按学生messages内容去重后分别418/508条。按原始行选256条时，101采样种子的随机组仅有223/231种内容，低NLL组只有158/182种。因此正式协议把两组支持均定义为256条任务内不同内容，记录全局内容数及任务内内容数。旧的行支持配方和试跑归档在`preparation-v0-row-support/`，未用于正式新模型训练；本调整发生在Stage 3冻结和主训练之前。

逐任务支持配额以原池示范数比例确定，稀有任务至少一条，总计256条；配额不使用模型表现。固定采样种子101/202/303/404，初始化/dropout种子同样四个。

对应单元沿用Stage 2相同物理GPU，随机与NLL两组交替执行先后顺序。SFT仍通过单独绑定入口调用原始冻结训练器，基础模型、LoRA、学习率及192步调度完全沿用Stage 2。实际输入和目标token数如实单列；主匹配预算是更新次数与样本次数。

任务内示范变化同时改变上下文、目标动作与频次分布，不能进一步单独归因为某一个属性。跨来源任务覆盖和任务类型比例本轮没有匹配；主比较在来源内部进行。
