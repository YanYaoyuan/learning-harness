# 优化器感知梯度选样：预热与评分试验

本阶段只预热一个独立LoRA特征模型、计算选样分数和候选清单。最终学生仍需从原基础模型另行训练；本阶段没有开发/确认任务评测、教师调用或论文效果检验。旧实验、评分和源码保持不变。

## 固定输入与预算

- 基础模型Qwen3-4B-Instruct-2507，revision `cdbee75f17c01a7cc42f958dc650907174af0554`；启动前后核验完整基础模型文件。
- 候选池是两个历史train监督语料按消息内容SHA去重的并集，预期853条；保留每条原语料到唯一内容的映射。所有训练/评分使用原assistant-only编码、max_length2048，不截断或按结果丢样本。
- 目标支持仅使用已固定的四条公开ReAct放置/清洗示例转换的40个JSON动作样本。它们的重置指纹与新校准/开发/确认任务不重合；目标支持只求梯度，不进入预热更新。
- SHA固定选取候选池的43个不同内容（约5%），seed20261113；完整洗牌遍历后续接部分遍历，产生128次呈现。LoRA r16、alpha32、dropout0.05、q/k/v/o_proj；AdamW lr1e-4恒定、betas0.9/0.999、eps1e-8、weight_decay0，batch1累计4，32个更新，梯度范数裁剪1.0。
- 在更新8/16/24/32后评分，四个检查点权重均为1/4。模型权重BF16，LoRA及特征FP32；SDPA；梯度检查点开启。评分时保持检查点机制、禁用全部Dropout，attention_dropout必须为0；无BatchNorm。CPU线程4。
- 物理GPU0单任务；总计账上限2 GPU小时，单次最多7100秒，不足1800秒不启动。无自动重试。所有forward/backward在执行前落盘attempt，完成或异常后记账；中断记录保留。

## 与官方LESS的对应

参考固定commit `8abf9628b9a814ac3045445eebc8ba3c908fdc78` 的 `collect_grad_reps.py` 与 `matching.py`。

对检查点c、候选x，先得到目标token平均loss的LoRA梯度g，再用**冻结的预热优化器状态**m/v构造：

\[
u_c(x) = \frac{0.9m_c+0.1g_c(x)}{\sqrt{0.999v_c+0.001g_c(x)^2+10^{-8}}}.
\]

此式沿用官方特征表达式，epsilon位于根号内；不把它描述成PyTorch带bias correction的AdamW实际一步更新。候选评分不修改m/v或权重。

支持样本y使用普通SGD梯度。每条梯度先单位化，在放置/清洗两个子任务内分别平均；候选更新向量也单位化。先对四检查点加权，再对两个子任务取最大：

\[
s(x)=\max_{k\in\{place,clean\}}\sum_c\tfrac14
 \left\langle\widehat u_c(x),\frac1{|S_k|}\sum_{y\in S_k}\widehat g_c(y)\right\rangle.
\]

本池足够小，直接用完整LoRA维度，无随机投影。支持均值流式累积，与显式候选×支持余弦矩阵的子任务均值数学等价，避免保存数十GB逐样本梯度。公开示例动作是支持单位；在每个任务族内按动作平均，较长公开示例具有更多动作权重，不能误称逐轨迹等权。

这是**适配到动作监督的LESS风格强基线**，不是原论文benchmark复现。记录差别：精确维度、两个目标任务族、固定小预热池和预算，以及受任务/动作配额约束的选样版本。额外输出无覆盖约束的全局top256候选以区分标准排序与覆盖控制；两者均未训练。

## 数值与完整性门槛

1. CPU/小张量检查：与官方Adam特征函数一致；流式相似度与显式矩阵一致；梯度符合有限差分；先跨检查点加权再取任务最大。
2. 每检查点重算第一条支持和第一条候选的梯度：余弦≥0.9999，相对L2误差≤1e-3；所有梯度、loss、分数有限，范数非零。失败即停止，保留现场。
3. 评分前后LoRA参数哈希、优化器m/v和CPU/CUDA随机流保持不变；训练参数只允许LoRA，基础权重不得有梯度。真实token、forward/backward数、预热loss和时间分别记账。
4. 所有4检查点、全部853候选和40支持完整才产生最终分数。每来源四配方的受控选样须维持768次呈现、256独特任务内容、逐位置任务/动作与层内独特支持配额。

这些是实现正确性门槛，不是判断方法优劣的显著性检验。分数分散或与NLL相关不代表已预测实际学习收益。

## 随后的学习比较与接口控制

新任务基础校准JSON9/32、ReAct21/32同时改变示例、思考和输出格式；原学生监督目标全部为JSON动作。在主比较前增加与JSON目标兼容的公共示例执行方式，或明确格式消融，避免将JSON/纯文本接口迁移当作技能差异。新128开发、128确认及官方测试仍保持未评测。

正式学习比较须另行冻结：候选低/中/高NLL、随机、梯度选样；独立初始化与采样；固定部署接口；目标支持信息和预热/特征成本的对照；二值结果统计校准及可负担的开发矩阵。最终SFT预算相同和总成本相同分别报告。先验证真实收益，再进行语料级预测和高/低/随机干预。
