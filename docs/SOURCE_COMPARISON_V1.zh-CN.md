# 核心对照：教师辅助采集→SFT，与 ReAct 自采→同预算 SFT

日期：2026-11-11。执行目录：`runs/source-comparison-v1/`。本轮是探索性强基线对照，不打开官方最终测试。

## 研究问题和比较对象

候选方案是 API 教师根据公开 reset 生成策略，辅助小模型完成任务，再通过成功轨迹 SFT 训练小模型。强对照是同一个小模型用 ReAct 自行采集成功轨迹，再使用相同预算 SFT。两种流程从同一 Qwen3-4B checkpoint 出发。

本轮不声称已经提出可发表的新方法。目标是检验此前观察到的数据收益和任务特定迁移，在强数据来源对照下是否仍然存在。两个采集 harness 同时改变了示例、提示形式和思考机制，因此比较的是完整流程，不能将差异只归因于教师卡片这一项。

## 采集与污染审计

- 72 个 A 训练任务，place/clean/heat；环境种子 11/23，每源 144 次单次尝试，两个来源都重新运行。
- 同一个本地执行器、逐请求采样 RNG、40 次调用、128 输出 token/调用、temperature 0.7。ReAct 的 think 消耗回合。真实输入/输出 token 均记录；相同最大调用预算不等于实际 token 或 FLOPs 相同。
- API 条件：原 JSON actor，既有教师策略只在前 4 回合可见。策略只依赖公开 reset。本轮新增 API 调用为 0，原始策略生成成本另计。
- ReAct 条件：固定官方 actor 示例 1、0，按公开目标路由；无教师策略，无失败反思和额外重试。
- 启动前用历史公开 reset 检查示例重合：A 查询中一条加热鸡蛋任务匹配 `react_heat_0`，两源共同排除，A 查询保留 23 个；B 的 cool/heat 各 32 个，A 训练仍为 72 个。规则为相同公开目标与可见编号容器集合，不按本轮结果筛选。不能据此排除预训练污染。

## 公平的训练输入与预算

只从成功尝试导出实际动作标签。API 与 ReAct 的训练输入都重建为：共同 JSON system、公开初始观察、最近 12 个实际动作/观察、规范化 JSON 动作目标。教师策略、示例、think 和其 OK 反馈不进入 SFT 输入或标签。保留历史失败动作的公开反馈，但无效格式、字面 `Nothing happens.` 不作为目标；长度超过 2048 的样本剔除。

按双方共同成功的 task/environment-seed 对匹配；每对取较少的合格动作数，两边均匀抽取相同数量，排序键相同。至少 8 个任务组、至少 4 个样本才训练，否则停止适应阶段并报告收集结果。这个筛选改变了估计适用的任务范围，不能冒称全部任务的数据质量因果效应。

每源重新训练 3 个 A adapter，seeds=101/202/303；LoRA r16、64 次更新、global batch 4，总共 256 次样本呈现。按相同样本键、相同种子配对；报告实际输入/目标 token、独立样本数和重复率。已有 9 个 SFT checkpoint 使用不同匹配集合，不直接复用成这轮候选模型，也不把旧分数加入新表。

## 后续适应与统一执行评测

沿用已冻结的 cool 与 heat B 教学序列，每条 512 个样本、128 次更新；保持样本顺序、B 初始化种子和优化器设置一致。cool 是 A 未训练的任务族，heat 是同族新任务，分别报告后再等权汇总。

每源 3 个 A 起点 × 2 个 B 任务族，共 12 条新轨迹。参数化为冻结 A、训练新增 B LoRA；这测试增量适应，不等于继续更新同一组权重的纯可塑性。复用 6 条已有 no-A B 轨迹的权重，严格核对数据和优化器配置，**全部评测分数重新运行**。

| 评测 | 检查点 | 执行方式 |
|---|---|---|
| B 主学习曲线 | 0 / 8 / 32 / 128 | 共同 JSON，无辅助 |
| B 执行方式检查 | 0 / 128 | 共同 ReAct，无教师卡片 |
| A 起点与遗忘 | A 起点、两族 B 终点 | 共同 JSON |
| A 强执行起点 | A 起点 | 共同 ReAct |

每次评测最多 40 调用、单次尝试、temperature 0、环境种子 11；没有测试时反思或跨任务记忆。三种训练种子不是三个独立评测集，统计中保留配对。BF16 和动态 batching 仍可能导致轨迹差异。

共同 ReAct 执行会提供冷却示例，其结果标为 few-shot 执行；不作为目标类型零示例迁移证据。预定总计 4,284 个评测任务运行。官方 seen/unseen 不开启。本轮查询集此前用于过旧实验，因此不冒充新鲜确认集。

## 分析承诺与解释边界

主比较：API − ReAct 的 JSON 执行下、两任务族等权平均归一化原始 AUC。以三个训练种子配对并在两族共享 bootstrap 的种子抽样，各族再按任务组重采样，4,000 次。

同时报告起点、终点、gain AUC、每个种子和任务族，配合 ReAct 执行的起终点检查。原始 AUC 混合起点和后续改善；gain AUC 也不能因果消除先验知识和天花板。不能仅根据某个显著/不显著数值宣判整个方向成立或失败。

如果辅助采集没有超过 ReAct 自采，就直接报告这一结果；如果差异保留，再分析任务覆盖、动作/上下文分布、训练 token 与初始能力。已有采集与迁移证据保留各自适用范围。

## 执行、追踪与恢复

```bash
PYTHONPATH=src MPLCONFIGDIR=/tmp/lh-mpl .venv-model/bin/python -m pytest -q
PYTHONPATH=src .venv-model/bin/python scripts/run_source_comparison.py --stage all
.venv-wandb/bin/python scripts/track_source_comparison.py --watch
```

主流水线自动采集、匹配、训练、适应、评测。W&B 观察器只读运行数据、记录进度，完成时自动核对真实调用/token、生成 PNG/PDF 和配对结果，上传到既有私有项目。进度指标只表示已完成任务；未完成时不比较两个实时胜率。

另有 `scripts/finalize_source_comparison.py` 独立等待流水线完成并生成本地报告，避免云端断线阻断本地收尾。报告生成使用文件锁，完整结果默认不重复覆盖；主动修图可使用报告脚本的 `--force`。

执行输入、教师缓存、数据集及 no-A 权重记录校验值。恢复核对冻结输入，已完成任务不重跑；半成品训练会报错并保留目录供检查。最终统计只纳入已提交的 run_id，不计中断残留轨迹。错误不自动计为任务失败。
