# Harness 是否培养了更好的学习者：研究质疑与最小实验

日期：2026-11-09。本文细化 V2 的第二个方向，记录支持理由、反对意见、可推翻条件和首轮实验。没有训练实验结果；方法均为候选设计。

## 1. 当前立场

值得研究的问题是：harness 在提高即时任务表现的同时，如何改变模型获得持久决策能力的过程？

“训练有帮助、部署撤帮助”已有直接工作，不能作为核心创新。候选贡献应是：在可控干预下识别即时收益和学习收益的分歧，解释分歧的条件，并用该解释改进学习目标或支持策略。

## 2. 三个分开的对象

固定基础工具、任务接口和环境观测，用 H0 表示基础 harness。额外支持 H 可以提供规划提示、诊断或纠错建议。

- 即时收益：固定模型，在 H 下是否更容易完成任务。
- 持久收益：由 H 产生经验并完成相同预算的训练后，在 H0 下的未见任务表现。
- 后续学习能力：学完 A 后，在 B 上按相同协议适应的速度，以及 A 的保持情况。

撤除的是额外支持；保留基础工具和获得任务事实的合法路径。上下文、外部记忆与 KV cache 都需重置，才能将参数能力与持久外部状态区分。

## 3. 最接近工作的边界

| 工作 | 已覆盖的内容 | 对本题的约束 |
|---|---|---|
| [SkillScaffold](https://arxiv.org/abs/2610.18807) | 按策略相关效用选择技能，训练后无技能推理 | 选择性注入、逐渐少用技能、撤除技能后变强均已有先例 |
| [HarnessBandit](https://arxiv.org/abs/2609.13739) | 用可学习性和梯度迁移信号调度多个 harness | 训练目标超越当前分数、跨 harness 调度均已有先例 |
| [EvoIn](https://arxiv.org/abs/2609.35290v2) | 演化决策流程，改写轨迹并内化，返回基础 harness | 将 harness 收益转成参数能力已有直接先例 |
| [Harness-Zero](https://arxiv.org/abs/2609.24974) | 将源 harness 指导转成目标动作空间下的修正与示范，再蒸馏 | 解决信息/动作接口不一致的蒸馏也已有直接工作 |
| [Rethinking Continual Experience Internalization](https://arxiv.org/abs/2606.04703) | 分析多轮内化坍塌与经验粒度、注入方式和训练分布 | 多轮保持与局部注入本身不足以确立新意 |

## 4. 对抗式质疑后的判断

### 质疑一：更强帮助提高示范质量，怎么会阻碍学习？

这是合理的竞争假设。强支持可能让学生接触此前无法到达的成功状态，也可能产生最好的蒸馏数据。研究不预设“帮助越少越好”。应比较支持内容、注入时机、学生能力与训练目标的交互。

尤其需要区分：支持代做了决策但没有把决策教给学生；支持给出可模仿的正确决策；支持保留学生尝试并提供可关联的反馈。这些条件可能产生相反结果。

### 质疑二：这只是蒸馏或 curriculum learning？

若贡献仅是渐退提示、先试后教或多轮重试，接近已有教学/课程方法。需要新的可重复现象、可解释的干预效应，以及对强蒸馏/自适应注入基线的增益。标题中出现 harness 不能代替差异论证。

### 质疑三：撤掉支持后变差，只是输入分布变了？

可能成立。统一在 H0 评测只是目标定义，尚不能解释原因。应加入混合有/无支持训练、目标视角的训练数据、相同内容不同注入时机，并测试新任务和改写接口。若混合上下文训练就完全消除差别，结论应收窄到分布匹配。

### 质疑四：高成功率使 GRPO 全组同分，当然没梯度？

在二值奖励下，若一个组内所有 rollout 奖励相同，任务 advantage 会退化。这是已知优化现象。若发现仅由这一点解释，不能宣称一般的 harness 促学机制。应检查混合组、有效任务梯度、KL 项，并用示范蒸馏或另一种合理训练设定做压力测试。

### 质疑五：你把模型不可能知道的事实拿走了？

若支持提供目标接口无法获得的实例事实，撤除后要求模型准确恢复这些事实并不合理。主实验保持相同基础观测和事实获取能力；额外信息条件单独研究，不能混合归因。

### 质疑六：按轨迹成功率匹配之后，是否能说是因果？

不能直接这样说。成功率是支持干预后的变量；筛选成功轨迹可能改变样本组成。主实验从相同模型起点和预先分配的任务随机化支持条件，使用完整预定采样协议。事后匹配只作为辅助诊断，不能代替主要因果估计。

## 5. 最小实验

采用一个可克隆状态、自动验证的交互环境；先在 ALFWorld 或小型代码修复环境中选一个。主模型 4B。先做单一核心决策，例如是否先诊断、是否验证修复，不同时改变工具、上下文管理和规划架构。

四个支持条件：无额外支持；固定早期支持；随机提供支持；基于学生状态延迟或选择支持。关键比较使用同一候选建议库和同一支持调用额度，防止教师质量或信息来源不同主导结果。延迟建议需检查在实际状态下仍适用。

先进行无参数更新的 pilot，估计即时收益；再从相同 checkpoint 开始做短程学习，检查在 H0 上的持久收益。主比较由独立开发集选定，再在最终测试集和至少三个训练种子上检验。首先保留无支持和最有区分度的两个支持条件，避免一开始铺开大量实验。

两种预算分开报告：固定总交互/计算预算，用于实际效率；固定训练 token/更新预算，用于帮助解释学习过程。采集、教师生成、失败样本和验证成本均计入相应总成本，不能只数成功示范。

## 6. 从现象到方法的门槛

若支持的即时效用不能可靠预测其学习效用，可以在相同学生 checkpoint 上用少量候选批次做短更新，在独立开发 probe 上估计持久收益，再用收益选择支持。

该规则需要与当前成功率选择、随机选择、固定渐退、SkillScaffold 风格效用和 HarnessBandit 风格信号比较。probe 只来自开发分布，最终测试集不参与选择。短更新估计要验证能否预测更长训练收益。

第一版可采用有限候选和简单选择策略。只有存在稳定、可预测且可迁移的状态依赖时，才值得进一步训练 meta-RL。不同训练环境的收益不相等，不意味着必须用强化学习解决选择问题。

## 7. 与持续学习及 RSI 的关系

持续学习扩展：在 A→B→C 的任务流上，测量额外支持撤除后的能力积累、学习新任务的速度与旧能力保持。

RSI 扩展：将如何产生和选择支持的规则也作为可更新对象，比较更新后的规则是否在未见学习者或任务族上提高下一轮改进效率。固定改进器带来的求解性能提升应单独描述。

## 8. 停止与转向条件

- 最强即时支持也始终产生最强持久能力：不支持预设分歧，优先研究有效蒸馏。
- 差别可由总 token、任务难度或训练数据过滤解释：修正结论，不能归因于学习机制。
- 仅在 GRPO 全组同分时出现：作为特定优化问题处理。
- 仅在人工制造的单一环境出现：增加自然任务证据后再考虑广泛主张。
- 简单渐退或已有方法完全解决：需要另找机制或新的任务条件。

资源安排：API 每月 ¥1,000–5,000，集中用于离线建议与失败分析；本地 GPU 承担主要 rollout 和参数干预。先用 pilot 实测吞吐与噪声，再确定正式实验规模。当前仅完成研究设计。

### 9.1 先修正现有结论

最近 transfer-factorial-v1 的跨族主指标为来源与筛选规则的交互，原始 AUC 差 +1.38 个百分点，95% 区间 [-6.19, 8.06]。这没有支持预设交互假设，但不等于 API 的平均作用为零，更不等于 harness 学习方向被否定。加热共同任务条件下，API−通用提示原始 AUC +7.91，区间 [2.38, 14.23]，属于次级结果，不能事后替换主指标。

原始 AUC 与 gain AUC 的差异包含起点能力；减去起点不是可塑性的因果控制。B 阶段冻结 A LoRA，新增 B LoRA，测到的是该参数化下的适应表现，不能声称同一组已学习参数的持续可塑性。7,200 个重复回合不是 7,200 个独立任务。旧实验保留为探索依据与代码资产，不预设其必须进入具身论文主表。

### 9.3 建议检验的核心问题

在相同可执行纠正来源与帮助预算下，最大化当前回合成功的介入方式，是否也最大化撤除帮助后对新失败的自主恢复能力？如果两种效用存在稳定差异，能否用学生状态与纠正后可自主完成的程度，预测并选择具有迁移价值的介入？

具体候选机制是介入终点对学生状态覆盖的影响：完整接管可能完成任务却不让学生执行恢复后的过渡；局部纠正后交还控制可能暴露这段过渡。二者优劣必须实测，不能预设“少帮助更好”。固定接管长度、DAgger、风险门控完全解释收益时，不把它重新命名为新方法。

先固定教师和学生，只比较完整接管、短纠正后交还、随机/风险门控；观察介入长度、学生后续访问状态、无辅助恢复之间的关系。训练样本数、纠正动作数、环境步数与计算成本分别报告；训练 token/动作量配平只作为额外机制对照，不能删除真实总效应。

WAM 在第一轮作为行动策略参与同协议评测。后续若利用其预测选择介入，必须确认该模型确实支持所需的动作条件预测；不能把联合生成视频和动作误当成任意动作的可靠模拟器。预测指标须用真实仿真分支的执行结果验证。仿真状态分支与 oracle 只用于训练或上界，不得作为方法在测试时的隐藏特权。

### 9.4 环境与 baseline

| 阶段 | 环境 | 模型/对照 | 目的 |
|---|---|---|---|
| 工程校准 | 原版 LIBERO | 官方 π₀.₅-LIBERO，继而 OpenWAM 对应权重 | 检查视觉、动作坐标、归一化、控制频率、动作块和成功判定 |
| 最小机制实验 | LIBERO-RECOVER 的预留开发子集 | 固定 VLA；无帮助、完整接管、局部纠正、风险门控 | 确认真实失败存在恢复空间，并测辅助与无辅助两种效用 |
| 主要评测 | 未参与方法选择的恢复场景 + LIBERO-Plus | VLA 与 WAM 各至少一个；同骨干加/不加方法；CARE/适用的 DAgger 风格强基线 | 测恢复、分布变化与撤除帮助后的迁移 |
| 跨环境确认 | RoboTwin 2.0 | 可复现的 VLA、OpenWAM，资源允许时加入 LAW | 检验是否局限于 LIBERO；单独报告 clean/randomized |

原版 LIBERO 是复现校准与正常能力保持集，不只依靠其总成功率论证进步。LIBERO-Plus 与 LIBERO-RECOVER 仍属同一家族，不能把二者算作两个独立环境。RoboTwin 才是第二环境。π₀.₅ 是公开且可复现的强基线，不宣称其为所有任务的最新榜首；定稿前更新同协议公开方法。

公平比较分两层：系统表现表比较完整系统的成功率、时间与成本；同骨干消融固定 checkpoint、观测、执行器与预算，识别我们方法的增益。不同预训练量的 VLA/WAM 排名不支持“世界建模导致更好学习”的因果结论。

### 9.5 最小试验与继续投入门槛

1. 在独立环境中启动一套 π₀.₅-LIBERO 推理；固定版本和随机种子，先做少量工程回合。记录峰值显存、端到端吞吐、环境步与渲染开销。小样本只检查工程，不宣布复现论文分数。
2. 初始开发规模建议 8–12 个任务、每任务若干固定失败状态。以配对场景比较各介入，验证教师能够从这些状态恢复。教师若不会连续动作纠正，不能让文本 API 输出“看起来合理”的动作充当专家。采用验证过的恢复控制器/专家；特权状态的使用逐项披露并在训练条件之间一致。
3. 在固定帮助预算下采集不同介入数据；从同一学生 checkpoint 开始，相同更新规则、至少三个独立采集/训练重复。保留全部失败与无效帮助成本。训练后移除外部帮助、清空跨回合缓存，在新的任务/失败状态上测自主恢复。
4. 主指标定为固定总预算后的无辅助恢复率，并报告正常任务保持；次指标为采集成功率、干预动作数、环境交互步数、延迟和 API/GPU 成本。三点以上预算用于画真实学习曲线，不能以两个端点声称整个过程加速。统计以任务/场景分组，重复 reset 不伪装成独立任务。
5. 若朴素局部纠正与强 DAgger/风险门控等效，则不继续扩大新方法训练。如果只有在线辅助收益而没有撤除后收益，将结论收窄为执行系统；是否值得继续取决于相对 CARE/LAW 的增量，而非继续坚持学习能力主张。若出现可迁移、能预测的效用差异，再投入学习型选择器或 RL。

先导实验用于估算方差与吞吐；正式样本量及最小有意义效应在开启主评测前冻结。训练失败状态、开发失败状态和最终测试按来源任务/场景拆分；基准若没有合适训练划分，则从训练任务单独生成恢复场景，不能拿测试失败库训练。

### 9.6 资源与启动限制

当前两张 5090 每卡 32GB，可先分工为策略推理与仿真/小型监测模型，或串行采集后做 LoRA。openpi 官方一般估计推理 >8GB、LoRA >22.5GB、全量微调 >70GB；这些不是本机的 π₀.₅ 实测保证，也不包含所有渲染/历史开销。两张卡不能自动当作一张 64GB 卡。4×A100 40GB 可用于支持分片的后续训练，但不能据显存总和保证任意方案能跑。

LAW 官方完整训练及全量评测调度使用 4 节点×8 卡，同时提供单任务评测入口；这不证明单个任务必须 32 卡，也不证明我们的双卡能无修改运行。先测现成权重推理，不复现其大规模预训练。OpenWAM 显存同样待实测。
