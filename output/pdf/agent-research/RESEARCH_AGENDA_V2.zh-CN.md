# Agent 研究议题 V2：API 辅助的学习机制与递归自改进

> 第二个方向的近邻排查、对抗式质疑和最小实验已进一步细化为 [研究讨论 V3](LEARNING_HARNESS_DEBATE_V3.zh-CN.md)，其中补充 Harness-Zero，并提高了新颖性与因果证据要求。

日期：2026-11-09。资源：同机 4×A100 40GB、2×RTX 5090；前沿模型 API 预算每月 ¥1,000–5,000。

本轮按用户反馈重新定位：优先选择能够解释或改变 Agent 学习机制的研究问题。前一版以技能维护为主的建议保留作记录；当前选题建议以本文为准。

依据：对原始论文页面、摘要及相关方法描述进行定向检索。下述机制与预期结果均为待检验假设；尚未复现实验，也未确认每一项候选差异在全部近邻中都没有先例。

## 1. 当前判断

**最有野心的主线：Agent 能否学到跨任务、跨学习者可迁移的自改进规则？**

**最适合目前资源优先启动的切口：让当前表现更好的 harness，是否也最有利于模型学习；怎样构造对学习真正有益的 harness？**

两者的共同目标是提升后续学习能力。API 可以承担提出机制、生成可验证的练习环境和分析失败的工作，本地模型承担真实学习与因果实验。

小模型的角色可以很明确：它是能够被多次重置、训练和干预的研究对象。用小模型完成清楚的机制论证，不妨碍研究问题具有较高层次。

## 2. 方向一：学习可迁移的自改进规则

工作标题：Learning Transferable Self-Improvement Operators for Language Agents。

### 研究问题

给定一个 Agent 的当前能力、失败轨迹与近期学习历史，能否学会产生“下一步应该如何练习”的策略？在新的任务家族、模型初始状态或模型规模上，这个策略能否仍然提高学习效率？

外层对象是改进算子 gφ；内层对象是任务策略 πθ。为保证可归因，第一版将改进算子的行动限制为：生成或选择下一批可执行的练习任务，以及有限种反馈形式。暂时固定优化器和基础 harness。

内层执行 θ' = U(θ,D[gφ])。外层用更新前后在独立开发任务上的能力变化评价 gφ，并将后续若干轮的保持和迁移纳入目标。最终测试任务家族完全不参与外层奖励。

### 最重要的近邻

- [SOAR: Teaching Models to Teach Themselves](https://arxiv.org/abs/2601.18778v3)：已经用学生在困难问题上的真实改善训练生成课程的教师。不能将“用学习增益作为元奖励”本身当作新意。
- [MetaSkill-Evolve](https://arxiv.org/abs/2607.05297)：已经在冻结 backbone 上演化改进流程的 meta-skill。不能只增加一个慢时间尺度就称为新机制。
- [ActiveSaddler](https://arxiv.org/abs/2610.00906)：课程随 harness 演化，按失败模式选择优化目标。
- [Absolute Zero](https://arxiv.org/abs/2505.03335)、[Agent0](https://arxiv.org/abs/2511.16043)：自生成任务和工具锚定的自演化。
- [Selection Is Not Learning](https://arxiv.org/abs/2610.22029)：任务可学与实际参数更新有益之间存在差距。

### 候选突破点

优先检验**改进规则本身的迁移**：在部分任务族、部分学习者状态上学会的规则，在未见学习者和任务家族上是否仍有用？其次检验只优化即时增益的策略，是否会牺牲后续学习能力。

有价值的结果应超过“同一个学生在同一批难题上被教得更好”。例如，算子在 4B 的若干训练阶段学到后，对新的 4B 初始状态、1.7B/8B 学习者、不同任务组合仍有稳定收益。规模迁移与能力状态迁移应分别测量。

这个定位仍需精读 SOAR、MetaSkill-Evolve 及后续工作，确认它们对跨学习者迁移和长程元目标已有何种覆盖。

### API 和本地算力如何协作

1. API 为若干代表性失败生成有限数量的练习方案、反例或环境变体。
2. 本地执行器验证任务可解性；从同一个学生 checkpoint 出发，用相同训练步数测试候选方案。
3. 将候选方案、学生状态摘要与实测增益构成元训练数据。先检查是否能预测有效干预，再决定是否训练一个小型改进策略。
4. 外层采用黑盒增益估计或策略优化，不依赖 API 的梯度或 logits。API 教师无需参与每条本地 rollout。
5. 正式测试撤除 API 教师，检验学到的算子能否独立迁移。

### 必须具备的证据

- 相同起始 checkpoint、相同总训练与生成预算下，与随机练习、难度匹配课程、固定 API 教师建议比较。
- 比较只看当前失败、使用学习历史，以及优化单轮/多轮增益的算子。
- 在未见任务族和未见学生状态上测达到目标水平所需预算。
- 分开报告求解能力和改进效率。一次 benchmark 分数提高不足以证明递归改进。
- 若改进算子在部署时固定，应称为学到的改进策略；只有继续更新改进机制并验证其后续收益，才能支持更强的 RSI 主张。

### 主要风险

每次元决策都需要训练和评估一个学生，外层奖励昂贵且噪声大。最初可用 1.7B–4B 和短 LoRA 更新建立证据，再对关键结果增加训练长度。若短更新下的排序无法预测较长训练收益，需要先解决元奖励可靠性。

## 3. 方向二：当前最优的 harness，是否也是学习最优的 harness？

工作标题：Do Better Harnesses Make Better Learners? Optimizing Scaffolds for Durable Agent Learning。

### 核心假设

**最大化当前任务成功率的 harness，可能与最大化模型长期独立能力的 harness 不同。**

这需要实验检验。例如，一个模块替模型完成任务分解或错误纠正，可能提升当轮成功率，却减少模型亲自做出相关决策的机会；另一种 harness 保留诊断反馈和适度探索，当前表现略低，后续学习和迁移却可能更好。更强帮助也可能产生更优训练轨迹、从而促进学习，方向和条件都不应预设。

### 为什么值得优先做

它直接连接 harness、参数学习、小模型与 agentic RL。论文的核心可以是一项清楚的机制发现，以及一个由证据支持的学习目标；不需要一次性构建复杂自演化系统。

核心目标可以写为：在固定资源下，选择训练期 harness，使模型在移除该 harness 后的未见任务表现、后续适应速度与旧能力保持更好。基础工具接口可继续保留，撤除的是额外支持机制。

### 最近近邻与差别

- [SkillScaffold](https://arxiv.org/abs/2610.18807) 已研究策略自适应技能效用、选择性注入和无技能推理。
- [HarnessBandit](https://arxiv.org/abs/2609.13739) 已结合可学习性与跨 harness 迁移信号进行调度。
- [EvoIn](https://arxiv.org/abs/2609.35290v2) 已将演化的决策流程内化到参数，撤除演化 harness 后评估。
- [Rethinking Continual Experience Internalization](https://arxiv.org/abs/2606.04703) 已分析多轮内化坍塌、经验粒度和注入方式。

所以，简单的“先加技能训练、再撤技能测试”不足以构成贡献。候选贡献应是：明确区分支持模块对即时求解与后续学习的因果影响，识别影响方向反转的条件，并让学习型目标据此选择支持方式。

### 最小而有判别力的实验

选择同一个 4B 起点和一组自动验证的交互任务。API 仅用于离线设计少量支持模块；模块冻结后，在本地重复训练实验。

支持方式可包含：任务分解提示、只提供诊断反馈、完整纠正建议、观察压缩、固定/逐步撤除支持。先固定一两类支持，避免同时改变大量因素。

分开做两组实验：

1. **交互效应组**：从同一模型起点出发，随机分配支持方式，在相同总预算下产生轨迹并训练，测整体效果。
2. **数据效应组**：对轨迹按长度、成功率和难度匹配，或对同一状态随机提供不同支持，区分数据质量、探索机会和提示依赖的贡献。

评估包括训练期成功率、撤除额外支持后的能力、新任务族迁移，以及学习下一批任务时的样本效率。支持模块的 API 生成、token 和验证成本全部单独记录。

关键消融是比较“按当前成功率选择支持”和“按独立能力/未来适应收益选择支持”。如果两种选择产生稳定不同的排序，并且局部干预能解释这种差别，就得到了一项可延展的机制结果。

### 为什么它适合成为方向一的起点

方向一需要知道“什么样的干预真的让 Agent 更会学习”。方向二先建立可测的学习信号和干预集合，再训练跨任务改进算子，能减少外层 RL 的盲目搜索。

## 4. 方向三：自改进依赖什么样的可验证信号？

工作标题：Identifiable Learning Signals for Recursive Agent Improvement。

研究问题：Agent 能改变任务、harness 和评价规则时，哪些证据足以区分真实能力增长与评价偏好漂移？在有限外部验证预算下，应检查哪些更新？

可从有明确正确性判据的环境开始，逐步隐藏部分判据，允许学习型评价器指导演化。比较评价器分数、独立执行结果和跨任务迁移之间何时发生系统性背离。理论部分可研究：当两种环境在可见反馈上不可区分，却对候选更新的优劣排序相反时，自改进选择能保证什么。

已有 [RuHarness](https://arxiv.org/abs/2610.36826) 研究 rubric 与 harness 共演化，因此“让评价规则也变化”已有先例。若做这个方向，需要给出可识别性条件、反例或有依据的外部验证分配算法。

这是概念层次很高、但需要较强理论与评估设计的方向。当前优先级低于前两个，适合作为有明确方法论兴趣时的选择。

## 5. 资源与 API 预算安排

本地 4×A100 40GB 适合承担 4B 级模型的主实验、短程学习干预与 LoRA 训练；2×5090 可承担独立评测和候选执行。外层元训练的可用规模由真实训练时长决定，不能只看显存。

每月 ¥1,000–5,000 的 API 应集中用于少量高价值研究动作：

- 初始候选支持机制或练习方案生成。
- 代表性失败的诊断和反例设计。
- 少量跨模型复核。

大量轨迹、任务执行、参数更新和主要评分在本地完成。先固定月度花费上限，再用实际输入/输出 token、缓存和调用单价决定采样量。此次调研没有调用付费模型 API，也没有读取或使用 API 密钥。

API 的价值在于扩展可提出的候选和可检查的假设。前沿模型的建议仍需用本地真实学习结果验证。若收益主要依赖持续由 API 代做关键决策，应单独报告该系统的成本与能力，不能归到小模型自身。

## 6. 建议的启动顺序

**先启动方向二，同时以方向一作为长期主线。**

第一阶段精读 SOAR、MetaSkill-Evolve、SkillScaffold、HarnessBandit、EvoIn 和 Rethinking Continual Experience Internalization。做一张近邻表，明确它们是否已有跨学习者迁移、支持效应归因、多轮学习收益和 teacher 撤除实验。

第二阶段建立同起点、同预算的 4B 干预实验。先回答即时成功率与后续学习收益是否会发生稳定排序差异，并排除额外 token、训练量和数据难度的解释。

第三阶段依据结果决定方法：若差别可由简单支持规则稳定解释，先形成机制论文；若收益强烈依赖学习者状态且存在可预测性，再训练学习型 harness 或改进算子。

将复现实验跑通和发现新现象分别作为里程碑。当前最值得追求的结果是：**证明并解释 Agent 的求解能力与学习能力可以被不同的系统设计分别优化，进而学到可迁移的改进规则。**
